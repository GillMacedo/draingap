# Architecture

draingap is one Go program in `plugin/scripts`, using only the standard library, so the installed plugin builds with `go build` and no module download. YAML is read with go.yaml.in/yaml/v2 v2.4.2, copied into `yaml_*.go` with the package renamed (Apache 2.0 and MIT, see `YAML_LICENSE` and `YAML_NOTICE`).

## Flow

1. **Manifests (`manifest.go`).** Each file is read whole. JSON must decode as exactly one value. YAML is split on `---` lines, and each document is parsed on its own so errors carry a line number. Documents without `apiVersion` and `kind` are refused, which catches error output from `helm`, `kubectl` and `go build`. A workload document with a template expression is refused as unrendered. If the last document is a workload and the file doesn't end with a `---` or `...` line, the file is refused as possibly cut off. For each container of each Deployment, StatefulSet, DaemonSet, ReplicaSet, Job, CronJob, Pod or List item it reads the grace period, preStop hook, stop signal, command, args and env, and refuses values the API server would reject.
2. **Container choice (`draingap.go`, `pick`).** One container, or the ones `--container` names.
3. **Program (`load.go`).** `go list -deps -export -json` in `--pkg` with `GOOS=linux`, `GOTOOLCHAIN=local` and `CGO_ENABLED=0` unless set. `-export` compiles every package, so code that doesn't build is refused. The target must be a `main` package with `func main`. Each package of the main module is parsed and type-checked with `go/types`, importing dependencies from the export data the go command built. Dependencies are only scanned for `os/signal` calls.
4. **Analysis (`program.go`).** Objects are keyed by package, name, file and line (`okey`), because each package is type-checked on its own and the same function is a different `types.Object` in each package that imports it. `index` records every assignment, `flag`/`pflag` duration registration, function, parameter and call site. `markReachable` walks static calls and function values from `main` and `init`; calls through an interface method reach every method of that name. `scan` then records, in reachable code only, `signal.Notify`/`NotifyContext`/`Ignore` calls with their signal values, `(*http.Server).Shutdown` calls with the classified context (`classifyCtx`) and the sleep before them (`sleepBefore`), and Serve calls with whether the program exits as soon as Serve returns (`exitsAfter`). Durations are evaluated by `evalDur`: constants from `go/types`, flags, `time.ParseDuration(os.Getenv(...))` with a fallback, variables with one assignment or the last one in the same block (`pickAssign`), and parameters through all callers. Fields with struct tags or of structs passed by pointer to a call are unknown (`decoded`).
5. **Checks (`check.go`).** Program-wide findings first (DG2xx, DG106, DG901), then for each container the signal check against its stop signal, the shell wrapper check, and the time budget. Flag and env deadlines are resolved against the container (`resolve` in `manifest.go`). Unknown values produce notes and leave the budget unchecked.
6. **Report (`draingap.go`).** A timeline per container, then findings sorted by level and code. Exit 0, 1 by `--fail-on`, and 2 for every refusal, with nothing on stdout.

## Why the tests run real programs

The program checks are claims about what Go does when the signal arrives. `tests/drain_test.go` builds every program in `tests/testdata/progs`, runs it, starts a 1.5s request, sends SIGTERM, and checks that programs with an error-level program finding really lose the request (or keep running) and that the others finish it and exit. A new program check without such a program isn't verified.
